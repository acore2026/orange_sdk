# Patrol 自动准备两端身份

2026-11-11：手机控制端 1.2.7、眼镜 0.2.63 和狗端 `/identity/prepare`
需要同时更新。本改动针对手机 **Patrol 按钮**；眼镜直接语音入口仍走原有流程，
主动注销后请先通过手机 Patrol 恢复两端。Confirm 仍负责实际派遣。

## 使用流程

1. 手机设置眼镜地址和机器狗管理地址。机器狗默认 HTTP 8081，不能填 SSH 40032。
   该地址必须能从眼镜访问；只在本机建立 SSH 隧道不足以让眼镜访问。
2. 连接眼镜；即使眼镜或机器狗主动注销，Patrol 仍可点击。
3. 点击 Patrol 后：眼镜请求狗端准备并轮询结果；成功后校验/初始化眼镜身份、
   发布能力；两端完成后发现机器狗，展示待确认候选。
4. 用户点击或说 Confirm 后才建组并发送实际巡检请求。

手机发送 `{command: PATROL, request_id, area, language, dog_endpoint}`（JSON 字段）。
眼镜只提交一次 `POST /identity/prepare`，后续使用同一 request_id 查询
`GET /identity/status`。狗端返回 `ok=true,state=READY` 才进入眼镜准备阶段。
旧狗端会因缺少该路由失败，旧手机缺少 dog_endpoint 会被新眼镜拒绝。

## 身份与失败语义

- 有效身份及已发布的 Card 复用；不能无条件调用 registerCapabilities，
  因为 SDK 对 CARD_PUBLISHED 再注册会注销并轮换身份。
- 只有身份、尚未发布 Card：补齐能力发布。
- 主动注销成功：保留注销状态，App/狗端重启也不会立即自动注册；
  下次 Patrol 才申请新身份并发布能力。已注销的 ID 不会冒充有效身份复用。
- 核心网明确返回 AGENT_INVALID / AGENT_NOT_FOUND：本地 reset 后重新申请。
  网络超时、NOT_AUTHORIZED、订阅缺失等不能视为身份不存在，不自动清空。
- 发布 422 等失败保留状态并显示错误；不把局部完成当作就绪，也不通过反复注销
  掩盖网侧 Card 冲突。此类冲突需结合核心网日志单独处理。
- 准备/发现超时或失败会显示所在阶段和错误，允许再次 Patrol；不会自动 Confirm。
  操作应在无正在运行的巡检/视频会话时执行。

狗端准备和注销共享互斥及请求去重；跨操作复用同一个 request_id 返回 409。
手机原来的 Studio Reset 行为保持为独立命令，不属于身份准备流程。

## 验证

本机测试覆盖：已发布身份不轮换、补齐发布、注销后新申请、明确失效恢复、
超时/权限错误保留身份、失败不报就绪、注销后进程重启保持暂停、并发/去重，
以及 Android HTTP 端点和核心网结构化错误码。
实际验收需更新手机和眼镜 APK，注销两端后点击 Patrol，确认候选出现且狗未动；
再由现场人员执行 Confirm 验证真实派遣。
